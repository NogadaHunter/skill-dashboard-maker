# 스킬 분석·작성 기준 (STEP 2에서 사용)

스킬 하나당 아래 형식의 JSON 항목 하나를 만든다. 반드시 그 스킬의 SKILL.md를 끝까지 읽고, 거기 적힌 입력·트리거·산출물·단계에 근거해서 쓴다. SKILL.md에 없는 기능은 지어내지 않는다.

## 항목 형식

아래는 형식을 보여 주기 위한 **가상의 스킬** 예시다. 실제 항목은 사용자의 SKILL.md 내용으로만 채운다.

```json
{
  "name": "example-meeting-notes",
  "ko_name": "회의록 정리기",
  "category": "문서·보고서",
  "summary": "회의 메모나 녹취를 받아 결정사항과 할 일이 정리된 회의록 DOCX로 바꿔 준다.",
  "inputs": "회의 메모, 녹취록, 채팅 기록",
  "outputs": "회의록 DOCX 1개 + 할 일 표",
  "formats": ["DOCX"],
  "triggers": ["회의록 만들어줘", "이 메모 회의록으로 정리해줘", "회의 결과 문서로 만들어줘"],
  "prompt": "(파일 첨부: [회의 메모].txt)\n이 회의 내용을 회의록으로 정리해줘.\n회의명은 [회의명], 일시는 [날짜]야.",
  "situations": [
    {"title": "보고용으로 짧게", "prompt": "(파일 첨부: [녹취록].docx)\n결정사항 위주로 한 쪽짜리 회의록으로 정리해줘."},
    {"title": "할 일만 뽑기", "prompt": "이 회의 메모에서 담당자·기한이 있는 할 일만 표로 뽑아줘."}
  ],
  "tips": ["참석자와 날짜를 함께 주면 머리말이 정확해져요.", "양식을 말하지 않으면 기본 회의록으로 만들어요."],
  "related": ["example-email-summary"]
}
```

`hash`와 `files`는 넣지 않아도 된다(빌드 스크립트가 채운다).

## 필드별 기준

| 필드 | 기준 |
|---|---|
| name | SKILL.md 앞머리의 name 그대로 (skills_raw.json의 name과 같아야 함) |
| ko_name | 무엇을 하는 도구인지 드러나는 한국어 이름, 20자 안팎. 영어 이름 직역 금지 |
| category | 아래 8개 중 하나만 |
| summary | 입력 → 결과가 보이는 한 문장, 80자 이내 |
| inputs / outputs | 각 50자 이내. outputs에는 파일 형식과 개수를 적는다 |
| formats | 대문자 형식 목록: DOCX PDF PPTX XLSX HWPX HTML MD TXT PNG MP4 등. 파일을 만들지 않으면 ["대화 응답"] |
| triggers | SKILL.md description의 트리거 문장을 사용자가 실제로 칠 말투로 3~5개 |
| prompt | 바로 복사해 쓰는 기본 프롬프트. 바꿀 부분은 [대괄호], 파일이 필요하면 첫 줄에 "(파일 첨부: …)" |
| situations | 상황별 프롬프트 2~3개. 스킬이 모드·유형을 여러 개 지원하면 모드마다 하나 |
| tips | 2~4개. 필요한 커넥터·API 키·웹 검색, 지원 파일 형식, 자주 하는 실수 |
| related | 함께 쓰면 좋은 스킬 0~3개. skills_raw.json에 있는 이름만 |

## 카테고리 8개

| 카테고리 | 이런 스킬 |
|---|---|
| 문서·보고서 | 보고서·회의록·공문·기안문·이메일 정리·PPT |
| 콘텐츠·마케팅 | 블로그·뉴스레터·SNS·카드뉴스·홍보 문구·랜딩 카피 |
| 교육·강의 | 강의안·커리큘럼·교재·이러닝 스크립트·교육 제안 |
| 책·출판 | 출판 기획서·목차·원고 집필·문체 교정·출간 편집 |
| 기획·분석 | 제안서·PRD·리서치·분석 리포트·챗봇·에이전트 프롬프트 |
| 영상·디자인 | 영상 대본·쇼츠·모션그래픽·썸네일·디자인 |
| 데이터·자동화 | 데이터 분석·엑셀·증시·크롤링·정기 리포트·업무 자동화 |
| 기타 | 위 어디에도 맞지 않을 때만 |

## 문체 규칙

- 설명은 짧은 평서문(해요체 가능), 프롬프트는 사용자가 Claude에게 말하는 말투("~해줘", "~만들어줘").
- em dash(—), 과한 이모지, "혁신적인" 같은 홍보 문구를 쓰지 않는다.
- 사용자 맥락을 모르면 일반적인 예시를 쓴다. 회사명·사람 이름을 지어내지 않는다.

## 여러 개를 처리할 때

- 한 번에 8~10개씩 읽고 `/tmp/skill-dashboard/new_01.json`, `new_02.json` … 처럼 배치마다 JSON 배열로 저장한다.
- 저장할 때마다 `python3 -c "import json;json.load(open('파일'))"`로 JSON이 깨지지 않았는지 확인한다.
