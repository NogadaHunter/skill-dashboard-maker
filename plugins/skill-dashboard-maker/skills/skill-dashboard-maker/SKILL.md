# skill-dashboard-maker

등록된 스킬 폴더를 스크립트로 수집하고, 각 SKILL.md를 읽어 사용법을 정리한 뒤,
`assets/dashboard-template.html`에 넣어 **스킬 대시보드 HTML 한 장**을 만든다.
디자인은 템플릿이 정하므로 새로 짜지 않는다. Claude가 하는 일은 각 스킬의 내용을 정확하게 정리하는 것이다.

결과물: `skill-dashboard.html` (인터넷 없이도 열리는 단일 파일. 검색, 카테고리 필터, 스킬 상세, 프롬프트 복사, 라이트·다크 모드, 휴대폰 화면 지원)

---

## 시작 전 확인

- 이 스킬은 코드 실행(파일 생성) 기능이 켜져 있어야 한다. 꺼져 있으면 "설정 → 기능에서 '코드 실행 및 파일 생성'을 켠 뒤 다시 요청해 주세요"라고 안내하고 멈춘다.
- 스크립트 경로는 이 SKILL.md가 있는 폴더 기준이다. 아래에서 `$SKILL`은 이 폴더를 뜻한다(예: `/mnt/skills/user/skill-dashboard-maker`).

---

## STEP 0. 대시보드 이름 정하기

대시보드 제목은 **이 대시보드를 쓰는 사용자 본인의 이름**으로 만든다: "<이름>의 스킬 대시보드".
이 스킬 파일에는 어떤 개인·회사 이름도 들어 있지 않으며, 제목에는 사용자에게서 온 이름만 쓴다.

이름을 정하는 순서:
1. 이번 요청에 이름이 있으면 그 이름 (예: "김민지 이름으로 만들어줘"). 사용자가 제목 전체를 정해 주면("'마케팅팀 스킬 모음'으로 해줘") 그 제목을 그대로 쓴다.
2. 이전 대시보드를 첨부한 갱신이면 STEP 2의 `plan`이 출력하는 `OWNER`를 그대로 이어받는다. 다시 묻지 않는다.
3. 이 대화나 사용자 프로필·메모리로 사용자 이름을 이미 알고 있으면 그 이름을 쓰고, 첫 안내에 "대시보드 이름은 '<이름>의 스킬 대시보드'로 할게요. 바꾸려면 말씀해 주세요."라고 알린다.
4. 그래도 모르면 수집을 시작하기 전에 한 번만 묻는다: "대시보드 제목에 넣을 이름을 알려 주세요. 이름 없이 만들려면 '이름 없이'라고 해 주세요." 답이 '이름 없이'이거나 이름을 주지 않으면 '나의 스킬 대시보드'로 만든다.

지키는 것:
- 이 스킬의 예시·문서에 나오는 이름을 제목이나 본문에 쓰지 않는다. 회사명·소속·연락처를 덧붙이지 않는다(사용자가 직접 제목에 넣어 달라고 한 경우만 예외).
- 정한 이름은 STEP 4에서 `--owner`로 넘긴다. 제목 전체를 받았으면 `--title`로 넘긴다.

## STEP 1. 등록 스킬 수집

```bash
python3 $SKILL/scripts/collect_skills.py --out /tmp/skill-dashboard/skills_raw.json
```

- 기본으로 `/mnt/skills/user`(claude.ai), 없으면 `~/.claude/skills`(Claude Code)를 찾는다. 이 스킬 자신은 목록에서 뺀다.
- `NO_SKILLS_ROOT`가 나오면: `ls /mnt/skills/` 로 다른 위치가 있는지 확인하고, 있으면 `--root`로 다시 실행한다. 그래도 없으면 사용자에게 "등록된 스킬을 찾지 못했어요. 설정 → 기능(또는 사용자 지정 → Skills)에서 스킬이 켜져 있는지 확인해 주세요"라고 알리고 멈춘다.
- 출력된 스킬 수와 이름을 사용자에게 한 줄로 알린다(예: "등록된 스킬 23개를 찾았어요. 하나씩 읽고 정리할게요.").

## STEP 2. 갱신인지 확인 (이전 대시보드가 있을 때만)

사용자가 이전에 만든 `skill-dashboard.html`을 첨부했다면:

```bash
python3 $SKILL/scripts/build_dashboard.py plan --raw /tmp/skill-dashboard/skills_raw.json \
  --previous /mnt/user-data/uploads/skill-dashboard.html --out-dir /tmp/skill-dashboard
```

- 바뀌지 않은 스킬은 `reuse.json`에 그대로 담기고, 새로 분석할 스킬 이름만 `todo.txt`에 남는다.
- 추가·수정·삭제 목록을 사용자에게 먼저 짧게 알린다.
- 출력의 `OWNER`(이전 대시보드의 이름)를 STEP 0의 이름으로 이어받는다. 사용자가 이번에 다른 이름을 말했으면 그 이름이 우선이다.
- 첨부가 없으면 이 단계를 건너뛰고 모든 스킬을 분석한다(plan을 `--previous` 없이 실행해도 된다).

## STEP 3. 스킬별 분석 (핵심)

`references/writing-guide.md`를 먼저 읽고, 그 형식과 기준대로 스킬마다 항목을 만든다.

- 분석할 스킬마다 `skills_raw.json`의 `path`에 있는 SKILL.md를 **끝까지** 읽는다. `trigger_hints`는 출발점일 뿐이다.
- 8~10개씩 묶어 `/tmp/skill-dashboard/new_01.json`, `new_02.json` … 에 JSON 배열로 저장하고, 저장할 때마다 JSON이 열리는지 확인한다.
- 진행 상황을 배치마다 한 줄로 알린다(예: "20개 중 10개 정리했어요").
- SKILL.md만으로 알 수 없는 내용은 비워 두거나 일반적으로 쓰고, 지어내지 않는다.

## STEP 4. 대시보드 생성

```bash
python3 $SKILL/scripts/build_dashboard.py build \
  --raw /tmp/skill-dashboard/skills_raw.json \
  --data /tmp/skill-dashboard/reuse.json --data /tmp/skill-dashboard/new_01.json [--data … 배치 파일 모두] \
  [--previous /mnt/user-data/uploads/skill-dashboard.html] \
  [--owner "<STEP 0에서 정한 이름>"] [--title "<사용자가 정해 준 제목 전체>"] \
  --out /mnt/user-data/outputs/skill-dashboard.html
```

- 제목 규칙: `--title`이 있으면 그대로, 없으면 `--owner`로 "<이름>의 스킬 대시보드". 둘 다 없으면 갱신일 때 이전 제목을 이어받고, 처음이면 "나의 스킬 대시보드". 출력 첫 줄의 제목이 STEP 0에서 정한 것과 같은지 확인한다.
- 처음 만드는 경우 `reuse.json`이 없으면 그 `--data`는 빼고 배치 파일만 넣는다.
- `MISSING` 또는 `INCOMPLETE`가 나오면 해당 스킬 항목을 채워 배치 파일에 추가하고 다시 실행한다. `--force`는 쓰지 않는다.
- 템플릿 HTML·CSS·스크립트를 고치지 않는다. 문구나 디자인을 바꿔 달라는 요청이 있을 때만 결과 파일을 고친다.

## STEP 5. 전달

- `/mnt/user-data/outputs/skill-dashboard.html`을 사용자에게 파일로 전달한다(present_files). 아티팩트로 띄울 수 있는 환경이면 같은 HTML을 아티팩트로도 보여 준다.
- 마무리 메시지에 담을 것(짧게):
  1. 대시보드 제목, 정리한 스킬 수와 카테고리 수, 갱신이면 추가·수정·삭제 수
  2. 쓰는 법: 검색하거나 카테고리를 누르고, 스킬을 고르면 나오는 프롬프트를 [복사]해서 대화창에 붙여 넣기
  3. 언제든 열기: 파일을 저장해 두거나, 아티팩트라면 사이드바에 고정
  4. 갱신법: 스킬을 바꾼 뒤 이 파일을 첨부하고 "스킬 대시보드 갱신해줘"라고 말하기(자동으로 바뀌지는 않음)

## 품질 기준

- 수집된 스킬이 빠짐없이 대시보드에 들어갔는가 (build 출력의 스킬 수 = STEP 1의 스킬 수)
- 모든 항목의 기본 프롬프트가 그 스킬의 실제 트리거·입력에 맞는가
- 카테고리가 8개 기준 안에 있는가
- 회사명·사람 이름·수치를 지어내지 않았는가
- 제목과 본문에 사용자가 준 이름 외의 개인·회사·소속 정보가 없는가

## 오류 처리

| 상황 | 대응 |
|---|---|
| 코드 실행이 꺼져 있음 | 켜는 방법을 안내하고 멈춤 |
| NO_SKILLS_ROOT | 다른 위치 확인 → 없으면 스킬 활성화 안내 |
| 스킬이 0개 | "등록된 스킬이 없어요"라고 알리고 멈춤 |
| PREVIOUS_INVALID | 첨부 파일이 이 스킬로 만든 대시보드가 아님 → 처음부터 새로 만들지 물어봄 |
| 스킬이 아주 많음(40개 이상) | 배치를 나눠 진행하고 배치마다 진행 상황 보고 |
| SKILL.md가 비었거나 깨짐 | 그 스킬은 이름과 설명만으로 짧게 채우고 tips에 "SKILL.md 확인 필요"를 적음 |

## 파일 구성

```
skill-dashboard-maker/
├── SKILL.md
├── scripts/
│   ├── collect_skills.py      ← 등록 스킬 수집 (skills_raw.json)
│   └── build_dashboard.py     ← 갱신 비교(plan) · 대시보드 생성(build)
├── assets/
│   └── dashboard-template.html ← 대시보드 디자인 템플릿 (고치지 않음)
└── references/
    └── writing-guide.md       ← 스킬별 항목 작성 형식·기준·카테고리
```
